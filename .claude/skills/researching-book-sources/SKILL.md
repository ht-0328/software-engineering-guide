# 書籍の調査

## 使う場面

`research/orchestration/<題材>/00-plan.md` に問いが書かれていて、そのうち書籍で答えるものが割り当てられたとき。

**1冊だけを読んで結論を書かない。** 2冊以上を突き合わせ、共通点と食い違いの両方を出す。1冊にしか無い主張は、複数の本が支持する主張と重みが違う。その区別ができて初めて、読者は主張の強さを判断できる。

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 読む本を2冊以上選ぶ
- [ ] 手順2: 抽出ずみかを確かめ、無ければ取り出す
- [ ] 手順3: 該当箇所を探す
- [ ] 手順4: 前後を読んで要約する
- [ ] 手順5: 20-books.md に書く
```

### 手順1 読む本を2冊以上選ぶ

`research/sources.md` の「章と出典の対応」に、章ごとの候補が挙がっている。そこから始める。

分野の接頭辞（`CODE`、`DESIGN`、`ARCH`、`REVIEW`、`TEST`、`THINK`、`UI`）で当たりを付けてもよい。**分野が重なる本は多いため、接頭辞だけで絞り込まない。**

`SRC-WRITE-001` から `SRC-WRITE-004` の4冊は読み直さない。姉妹リポジトリ `engineering-docs-standard` が本編の出典として読み込みずみであり、その結論を参照する。

### 手順2 抽出ずみかを確かめ、無ければ取り出す

```bash
ls research/extracted/
```

必要な出典IDのファイルが無ければ、PDFから取り出す。引数はPDFのファイル名であり、対応は `research/sources.md` が持つ。

```bash
docker build -t guide-tools -f tools/Dockerfile tools/
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/w" -w /w guide-tools \
  python tools/extract_pdf.py code-review-textbook.pdf
```

1冊で1分ほどかかる。**引数を省略すると22冊すべてを処理するため、必要な本だけを指定する。**

### 手順3 該当箇所を探す

**抽出テキストは1冊で40万字ある。全文を読むと文脈窓を使い切る。** 同梱の道具で、該当する行とページ番号だけを引く。

```bash
docker run --rm --user "$(id -u):$(id -g)" -v "$PWD:/w" -w /w guide-tools \
  python .claude/skills/researching-book-sources/scripts/search_extracted.py \
  SRC-REVIEW-001 レビュー 承認 --all-terms --context 2
```

| 引数 | 働き |
|---|---|
| 第1引数 | 出典ID。`all` で抽出ずみ全冊を横断する |
| 第2引数以降 | 探す語。1つ以上 |
| `--all-terms` | すべての語を含む行だけを返す。既定はいずれかを含む行 |
| `--context N` | 前後にN行を添える |
| `--max N` | 返す件数の上限。既定は40 |
| `--variant` | `poppler`（既定）か `pypdf`。段組の復元が崩れたら切り替える |

出力は `SRC-REVIEW-001 p.219 L9183 | 本文` の形である。**`p.` はPDFのページであり、紙の本のノンブルとは一致しない。** この注記は `research/sources.md` にある。

語が思いつかないときは、まず `all` で広く引き、返ってきた本文から本が使っている語を拾う。**書籍は書き手の語彙で書かれており、こちらが考えた語では当たらないことがある。**

### 手順4 前後を読んで要約する

該当行だけで主張を書かない。`--context` を増やすか、行番号の前後を直接読む。

```bash
sed -n '9150,9230p' research/extracted/SRC-REVIEW-001.poppler.txt
```

読むときに確かめるのは次の3つである。

| 確かめること | なぜか |
|---|---|
| その記述が著者の主張か、紹介した他説か | 紹介を著者の主張として引くと出典を誤る |
| 条件が付いていないか | 「新人が多い場合」のような条件は要約で落ちやすい |
| 数値に測定の裏づけがあるか | 経験則と測定値では、読者の使い方が変わる |

### 手順5 20-books.md に書く

書式は `writing-interim-artifacts` に従う。主張IDの接頭辞は `B-` を使う。

「根拠の所在」の欄には、**出典IDとページ**を書く。章・節の番号が本文から読み取れるなら、それも添える。

```markdown
| `B-1` | 指摘は観点と根拠と代案の3点で書く | `SRC-REVIEW-001` p.87（3.2） | 一次資料 |
```

食い違いを見つけたら、そのまま書く。**どちらが正しいかをここで決めない。** 決めるのは議論の段階であり、この成果物は材料を出す場である。

```markdown
## 本どうしの食い違い

| 論点 | この本 | 別の本 | 条件の違い |
|---|---|---|---|
| 指摘の量 | `SRC-REVIEW-001` p.102: 重大なものに絞る | `SRC-CODE-002` p.55: 気づいた点はすべて出す | チームの練度 |
```

**要約で書く。原文を長く写さない。** 参考書のPDFは購入者を特定できる情報を含み、抽出テキストは原本の複製にあたる。`research/orchestration/` はGitで追跡する。

## 確かめること

- [ ] 2冊以上から引いている
- [ ] 主張1件ごとに出典IDとページがある
- [ ] 1冊にしか無い主張が、そう分かるように書いてある
- [ ] 食い違いを、決着させずに記録している
- [ ] 数値に、測定か経験則かの区別を添えている
- [ ] 連続する3文以上の転載が無い
