# 検査で落ちる型と、直した形

`tools/doc_lint.py` が報告する項目のうち、書いていて踏みやすいものを挙げる。**規則の本文はここに写していない。** 規則そのものは `engineering-docs-standard/docs/` と `engineering-docs-standard/.doclint.yml` にある。

重大度が `error` のものは、1件でも残ると終了コード1で失敗する。`warning` は失敗しない。

## error になるもの

| 検査名 | 落ちる例 | 直した形 |
|---|---|---|
| `single_h1` | 1ファイルに `#` が2つ | 2つ目を `##` にするか、ファイルを分ける |
| `heading_level_skip` | `##` の次に `####` | `###` を挟むか、`###` に下げる |
| `heading_max_depth` | `#####` を使う | 文書を分ける。4段までに収める |
| `empty_section` | 見出しの直後に別の見出し | 見出しの下に、その節の要点を1文置く |
| `heading_no_period` | `## 何を見るか。` | `## 何を見るか` |
| `double_negative` | 「出典が無いと書けない」 | 「出典があるときだけ書く」 |
| `style_mixing` | 常体の文書に「です」「ます」が混ざる | 常体（である）にそろえる |
| `list_style_mixing` | 1つの箇条書きで文体が混ざる | どちらかにそろえる |
| `table_columns` | 行によって列数が違う | 区切り記号の数をそろえる |
| `code_block_language` | ` ``` ` だけで始める | ` ```bash ` ` ```text ` ` ```markdown ` を付ける |
| `link_text` | `[こちら](x.md)` | `[ADR-001 リポジトリの構成](x.md)` |
| `broken_local_link` | 相対パスの誤り | 書いたパスでファイルが開けるか確かめる |
| `broken_anchor` | `](#見出し)` の綴りが本文と違う | 見出しの文字列をそのまま写す |
| `undefined_reference` | `[語][ref]` の定義が無い | 定義を置くか、通常のリンクにする |
| `unresolved_marker` | `TBD` `TODO` `FIXME` `???` `未定` | 決まっていないことを日本語の文で書く |
| `term_consistency` | 同じ文書に「ユーザー」と「ユーザ」 | どちらかにそろえる |

`unresolved_marker` は、印を消すだけでは直っていない。**「何が決まっていないか」と「決まったら誰が書くか」を本文に書く。**

## warning になるもの

失敗はしないが、読み手には響く。

| 検査名 | 落ちる例 | 直した形 |
|---|---|---|
| `vague_words` | 「適宜」「必要に応じて」「可能な限り」「十分に」「速やかに」 | 数値、固有名詞、日時に置き換える |
| `timeless` | 「今後」「最新の」「現時点では」「従来の」 | 日付か版数で書く |
| `vague_heading` | `## その他` `## 詳細` `## 補足` `## 備考` `## 参考` | 中身を表す語を見出しにする |
| `open_in_hiragana` | 「出来る」「下さい」「又は」「更に」「但し」「予め」 | 「できる」「ください」「または」「さらに」「ただし」「あらかじめ」 |
| `sentence_length` | 一文が50字を超える | 主題ごとに文を切る |
| `commas_per_sentence` | 読点が4つ以上 | 係り受けが一意になるまで切る |
| `paragraph_sentences` | 段落が8文以上 | 話題ごとに段落を分ける |
| `list_items` | 箇条書きが8項目以上 | まとめるか、表にする |
| `table_cell_length` | 1セルが3文以上 | セルは結論だけにし、説明は本文へ出す |
| `bare_url_link` | URLをそのままリンク文字列にする | ページ名を文字列にする |
| `image_alt` | `![](図.png)` | `![構成図](図.png)` |

## 検査に出ないが落ちるもの

**機械で見つからない。人が確かめる。**

| 見るもの | なぜ検査に出ないか |
|---|---|
| 出典IDと該当箇所が主張に付いているか | 形式は正しく、中身が正しいかを判定できない |
| 出典の要約が原文の主張とずれていないか | 原文と照合する仕組みが無い |
| `zensical.toml` の `nav` に章が入っているか | 検査の対象が Markdown だけである |
| 書籍の本文を長く写していないか | 引用と要約を機械で区別できない |

`nav` の漏れは `build_site.py` でも失敗しない。**サイトは作れるが、サイドバーに出ない。** 足したかどうかを目で確かめる。
