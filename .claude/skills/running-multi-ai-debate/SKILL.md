# 3者による議論

## 使う場面

`research/orchestration/<題材>/` に調査の成果物がそろい、これから最終文書を書くとき。

**1者の調査は、その者が知っている範囲でしか誤りを見つけられない。** 同じ問いに3者が答え、互いの成果物を批評すると、単独では気づかない見落としと、条件の違いによる食い違いが表に出る。議論はそのために行う。

## 決着のさせ方を先に決める

**多数決で決めない。** 次の3つで決める。

| 規則 | 内容 |
|---|---|
| 根拠の強さ | 一次資料に基づく主張を、二次資料や推測より優先する |
| 独立性 | **同じ資料を読んだ2者の一致は、2票ではない。** 資料の数で数える |
| 保留 | 決められないものは「決着しない」と書き、条件の違いを残す |

3つ目は `docs/index.md` の書き方の規則から来ている。決めていないことを決めたように書くと、読者が根拠の重みを判断できなくなる。**`TBD` や `FIXME` の印は残さない。「決着しない」と日本語で書く。**

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 論点を作る
- [ ] 手順2: 同じ入力を3者に配る
- [ ] 手順3: 批評を集める
- [ ] 手順4: 40-debate.md にまとめる
```

### 手順1 論点を作る

4つの成果物（`10-web.md`、`20-books.md`、`30-codex.md`、`31-antigravity.md`）を読み、論点を3種類の観点で拾う。論点IDは `D-1` から振る。

| 種類 | 見つけ方 | 例 |
|---|---|---|
| 食い違い | 同じ問いに違う答えが出ている | 指摘の量を絞るか、すべて出すか |
| 単独主張 | 1者だけが述べており、他が触れていない | 1冊だけにある数値 |
| 空白 | `00-plan.md` の問いに誰も答えていない | 承認の条件 |

**空白を論点に含める。** 誰も答えていないことは、議論の場でなければ気づかれずに最終文書へ持ち込まれる。

論点を作業用のファイルに書き出す。次の手順で依頼文に差し込む。

```bash
WORK=$(mktemp -d) && echo "$WORK"
```

表示されたパスを控え、`<作業ディレクトリ>/points.md` に論点の表を書く。列は「論点ID / 種類 / 争点」とする。

### 手順2 同じ入力を3者に配る

**成果物の中身をプロンプトに直接入れる。ファイルのパスを渡さない。**

理由は、3者に同一の入力を与えないと批評を比べられないためである。ファイルのパスを渡すと、読める範囲の違いがそのまま批評の差になり、意見の差と区別できなくなる。

依頼文を組み立てる。

```bash
TOPIC_DIR=research/orchestration/<題材>
WORK=<手順1で控えた作業ディレクトリ>
{
  echo "あなたは技術文書の査読者である。次の4つの調査結果と論点を読み、論点ごとに立場を述べよ。"
  echo ""
  echo "## 守ること"
  echo "- 論点ごとに「同意」「反対」「見落とし」のいずれかを選び、理由を1文で書く。"
  echo "- 根拠は、渡された資料の主張ID（W- B- C- A-）で指す。"
  echo "- 資料に無いことを述べる場合は、行頭に「推測:」と書く。"
  echo "- 出力は Markdown の表だけとする。前置きと後書きを書かない。"
  echo "- 表の列は「論点ID / 立場 / 理由 / 根拠」とする。"
  echo ""
  echo "## 論点"
  cat "$WORK/points.md"
  echo ""
  echo "## 調査結果"
  # 失敗した系統のファイルは無い。あるものだけを入れる。
  for f in 10-web 20-books 30-codex 31-antigravity; do
    [ -s "$TOPIC_DIR/$f.md" ] && cat "$TOPIC_DIR/$f.md"
  done
} > "$WORK/critique-prompt.txt"
wc -c "$WORK/critique-prompt.txt"
```

**組み立てた依頼文の大きさを見る。** 4系統で10万字を超えるようなら、主張の表だけを抜き出して渡す。渡す量が多いと、外部AIが論点ごとの判断ではなく全体の要約を返す。

2者へ同時に投げる。**どちらも3分から15分かかる。Bashの既定の待ち時間は2分であり、そのまま待つと打ち切られる。**

**2つを別々のBash実行として、どちらも背景で起動する**（`run_in_background` を真にする）。1つの実行の中で `wait` を使わない。`wait` は前面で待つため、同じ制限に当たる。

```bash
codex exec --cd "$PWD" --sandbox read-only --skip-git-repo-check \
  -o "$TOPIC_DIR/41-codex-critique.md" \
  "$(cat "$WORK/critique-prompt.txt")" > "$WORK/codex.log" 2>&1
```

```bash
agy --output-format text --print-timeout 15m \
  --print "$(cat "$WORK/critique-prompt.txt")" \
  > "$TOPIC_DIR/42-antigravity-critique.md" 2> "$WORK/agy.log"
```

**Antigravity が何も返さないときは、`~/.gemini/antigravity-cli/settings.json` の `permissions.allow` に道具が入っていない。** 標準エラーに拒否された道具の名前が出る。2者で進め、そのことを記録する。

`$WORK` と `$TOPIC_DIR` は展開して書く。**背景の実行はシェルの変数を引き継がない。**

投げたら、自分（このセッション）も同じ依頼文に答える。**他の2者の批評を見る前に答える。** 先に見ると、そちらへ寄る。自分の答えを書き終えるころに、2者の終了が通知される。

### 手順3 批評を集める

外部AIは失敗することがある。**失敗を隠さない。**

| 症状 | 意味 | すること |
|---|---|---|
| 出力が空で、標準エラーに `auto-denied` | Antigravity が道具の使用を拒否された | 拒否された道具名を記録し、2者で進める |
| 終了コードが0以外 | 実行に失敗した | ログの末尾を記録し、2者で進める |
| 表以外の文章が返る | 書式が守られなかった | 表の部分だけを採る。書き換えない |

`40-debate.md` の冒頭に、**何者が参加したか**を書く。2者だけで決着した論点は、3者で決着したものより弱い。

### 手順4 40-debate.md にまとめる

書式は `writing-interim-artifacts` に従う。論点ごとに1つの節を作る。

```markdown
### D-1 レビューで指摘する量をどこまで絞るか

| 者 | 立場 | 理由 | 根拠 |
|---|---|---|---|
| Claude | 重大なものに絞る | 全部出すと読み手が優先度を失う | `B-1`（`SRC-REVIEW-001` p.102、一次資料） |
| codex | すべて出す | 見逃しの費用が高い | `C-3`（推測） |
| Antigravity | 練度で変える | 新人には網羅が要る | `A-2`（推測） |

**決着**: 練度で変える。`B-1` は一次資料だが、対象を熟練者に限っている。範囲が違う主張であり、対立していない。

**最終文書での扱い**: 観点として書く。数値の基準は置かない。
```

最後に、決着しなかった論点をまとめて置く。

```markdown
## 決着しなかった論点

| 論点ID | 争点 | 決着しない理由 |
|---|---|---|
| `D-4` | 1回のレビューで読む行数の上限 | 一次資料が1件のみで、測定の裏づけが無い |
```

## 確かめること

- [ ] 論点に「空白」（誰も答えていない問い）が含まれている
- [ ] 3者に同じ入力を渡した
- [ ] 自分の立場を、他者の批評を見る前に書いた
- [ ] 参加できなかった者と、その理由が冒頭にある
- [ ] 決着の理由が、票数ではなく根拠の強さで書かれている
- [ ] 決着しなかった論点が、そう書かれている
- [ ] `TBD` `FIXME` の印が無い
