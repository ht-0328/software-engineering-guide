# 公開情報の調査

## 使う場面

`research/orchestration/<題材>/00-plan.md` に問いが書かれていて、そのうち公開情報で答えるものが割り当てられたとき。

**書籍22冊は2026年より前に出たものであり、規格の版数と各社の公開標準は書籍の外にある。** 公開情報を調べるのは、書籍が扱わない範囲を埋めるためである。書籍と同じことを言い直すためではない。

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 答える問いを確かめる
- [ ] 手順2: 一次資料を探す
- [ ] 手順3: 本文を開いて確かめる
- [ ] 手順4: 10-web.md に書く
```

### 手順1 答える問いを確かめる

`00-plan.md` を読み、自分に割り当てられた問いの番号を控える。**問いに無いことを調べない。** 4者が同じ問いに答えるからこそ、議論の段階で答えを並べられる。

### 手順2 一次資料を探す

`WebSearch` で探す。**探すのは原典であり、原典を解説した記事ではない。**

| 段 | 例 | 扱い |
|---|---|---|
| 一次 | 規格の本体、標準化団体の公式文書、査読つき論文、仕様書 | 根拠にしてよい |
| 二次 | 各社が公開する社内標準、規格の策定者による解説 | 「誰の立場か」を添えて引く |
| 三次 | まとめ記事、個人ブログの要約、生成AIの回答 | 根拠にしない。たどって原典を探す |

**三次資料を根拠にすると、言い換えの誤りを検出できない。** 手引きは根拠をたどれることを売りにしているため、たどった先が要約では意味が無い。

`research/sources.md` の「書籍以外の出典」に候補が挙がっている。そこから始めると早い。

### 手順3 本文を開いて確かめる

**`WebFetch` で本文を開く。検索結果の抜粋だけで主張を書かない。** 抜粋は文脈を落とすため、条件つきの記述が無条件の記述に見えることがある。

規格そのものが有料で読めない場合がある。そのときは、**読めなかったと書く。** 概要ページの記述から本体の中身を推定して書かない。

確かめるのは次の3つである。

| 確かめること | なぜか |
|---|---|
| 版数と発行年 | 規格は改訂される。版を書かないと後で照合できない |
| 発行した組織 | 同じ略称で別の組織の文書が存在する |
| その記述が要求か推奨か | 規格は両者を区別して書く。要約は区別を落とす |

### 手順4 10-web.md に書く

書式は `writing-interim-artifacts` に従う。主張IDの接頭辞は `W-` を使う。

「根拠の所在」の欄には、**URLと確認日の両方**を書く。公開情報は書き換わるため、URLだけでは後から同じものを見たと言えない。

```markdown
| `W-1` | ISO/IEC 25010 は品質特性を9つに分ける | https://www.iso.org/standard/78176.html （2026-09-03 確認、2023年版） | 一次資料 |
```

## 出典IDを振らない

**`SRC-EXT-<連番>` の採番は `research/sources.md` が一次情報である。** この調査の段階では番号を振らない。

理由は、調べた公開情報のすべてが最終文書の根拠になるとは限らないためである。仮番号を振ると、採用しなかったものが欠番として残り、番号の意味が薄れる。

正式な出典に採用すると決まった時点で、次の2つを行う。**この2つは、最終文書を書く段階の作業である。**

1. `research/sources.md` の「書籍以外の出典」に `SRC-EXT-<連番>` を追加する。
2. `research/external/` に1件1ファイルで調査結果を置く。

## 確かめること

- [ ] `00-plan.md` の問いに答えている
- [ ] 主張1件ごとにURLと確認日がある
- [ ] 三次資料を根拠にしていない
- [ ] 規格を引いた主張に版数と発行年がある
- [ ] 読めなかった資料を「読めなかった」と書いている
- [ ] `SRC-EXT-` の番号を振っていない
