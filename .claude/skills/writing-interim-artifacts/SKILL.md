# 中間成果物の書き方

## 使う場面

調査の途中で作るファイルを書くとき。`docs/` に置く最終文書ではない。

**中間成果物は、次に読むのが人ではなくAIである。** ここが最終文書との違いである。4者（公開情報の調査、書籍の調査、codex、Antigravity）の結果を並べて突き合わせるため、**誰の主張か、何をどこまで確かめたか、何を答えられなかったか**が主張1件ごとに判別できないと、議論の段階で使えない。書式をそろえるのはそのためである。

## 置き場所とファイル名

題材ごとにディレクトリを1つ作る。名前は英語の小文字とハイフンで付ける（例: `research/orchestration/code-review-criteria/`）。

| ファイル | 中身 | 書く者 |
|---|---|---|
| `00-plan.md` | 題材、答えるべき問い、割り当て | 司会 |
| `10-web.md` | 公開情報の調査 | 司会 |
| `20-books.md` | 書籍の調査 | 司会 |
| `30-codex.md` | codex の調査 | codex |
| `31-antigravity.md` | Antigravity の調査 | Antigravity |
| `40-debate.md` | 議論の論点と決着 | 司会 |
| `41-codex-critique.md` | codex の批評（原文のまま） | codex |
| `42-antigravity-critique.md` | Antigravity の批評（原文のまま） | Antigravity |

`41` と `42` は外部AIの出力をそのまま置く。**書式が崩れていても直さない。** 司会が書き換えると、決着の根拠が司会の解釈なのか外部AIの主張なのかを後から切り分けられない。

**`research/**` は doc_lint の対象外である。** 検査は落ちない。書式は自分で守る。

## 手順

写して、終わったものに印を付ける。

```text
- [ ] 手順1: 冒頭のメタ情報を置く
- [ ] 手順2: 主張を1件1行の表に書き、主張IDを振る
- [ ] 手順3: 答えられなかったことを書く
- [ ] 手順4: 転載していないかを確かめる
```

### 手順1 冒頭のメタ情報を置く

h1 の直後に、この表を置く。**「調べた範囲」を空にしない。** ここが空だと、議論のときに「触れていない」と「調べたうえで否定した」を区別できない。

| 項目 | 内容 |
|---|---|
| 題材 | （例: コードレビューで見る観点） |
| 答える問い | （例: `Q1`、`Q3`。`00-plan.md` の番号） |
| 調べた者 | （例: Claude Opus 5 / codex `gpt-5.6-sol` / Antigravity `gemini-3.1-pro-high`） |
| 調べた日 | （例: 2026-09-03） |
| 調べた範囲 | （例: `SRC-REVIEW-001` の抽出テキスト全文を検索。`SRC-CODE-002` は未検索） |

### 手順2 主張を1件1行の表に書き、主張IDを振る

**1行が1主張である。** 段落で書くと、議論のときに「どの主張への反論か」を指せない。

主張IDは、書いた者ごとに接頭辞を変える。

| 接頭辞 | 書いた者 |
|---|---|
| `W-` | 公開情報の調査 |
| `B-` | 書籍の調査 |
| `C-` | codex |
| `A-` | Antigravity |

| 主張ID | 主張 | 根拠の所在 | 確からしさ |
|---|---|---|---|
| （例: `B-1`） | （例: 指摘は観点と根拠と代案の3点で書く） | （例: `SRC-REVIEW-001` p.87） | （例: 一次資料） |
| （例: `W-2`） | （例: ISO/IEC 25010 は品質を9つに分ける） | （例: URLと確認日） | （例: 一次資料） |

「確からしさ」は3つから選ぶ。**これが無いと、議論で根拠の強さを比べられない。**

| 値 | 意味 |
|---|---|
| 一次資料 | 規格の本体、書籍の本文、公式文書を自分で読んだ |
| 二次資料 | 他者による要約や解説を読んだ。原典は見ていない |
| 推測 | 資料に書かれておらず、書いた者が補った |

**`research/extracted/` の抽出テキストは書籍の本文である。一次資料として数える。** PDFから機械で取り出したものであり、他者の要約ではない。ここを二次資料と数えると、書籍から引いた主張がすべて一段弱く見え、議論の決着が公開情報の側へ偏る。

### 手順3 答えられなかったことを書く

**「無い」ではなく「調べていない」と「調べたが見つからない」を分けて書く。**

この2つは、議論のときに意味が違う。前者は誰かが引き取れる作業であり、後者は資料の側に無いという発見である。

```markdown
## 答えられなかったこと

| 問い | 状態 | 理由 |
|---|---|---|
| （例: `Q2`） | （例: 調べていない） | （例: 該当の書籍が未抽出） |
| （例: `Q4`） | （例: 調べたが見つからない） | （例: 3冊を検索したが数値の記載が無い） |
```

### 手順4 転載していないかを確かめる

**要約で書く。原文を長く写さない。** 参考書のPDFは購入者を特定できる情報を含み、`research/extracted/` は原本の複製にあたる。`research/orchestration/` はGitで追跡するため、ここに原文を写すと複製が公開範囲に出る。

| してよい | しない |
|---|---|
| 主張を自分の言葉で1行に要約する | 段落をそのまま写す |
| 用語の定義を1文で引く | 定義の前後をまとめて写す |
| ページと章・節を書く | 本文の画像を貼る |

## 確かめること

- [ ] 冒頭の表に5項目がそろっている
- [ ] 「調べた範囲」に、見ていない範囲が書いてある
- [ ] 主張1件ごとに主張IDと確からしさがある
- [ ] 「答えられなかったこと」の節がある
- [ ] 連続する3文以上の転載が無い
