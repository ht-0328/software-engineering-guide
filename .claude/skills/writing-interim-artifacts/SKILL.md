# 中間成果物の書き方（司会の側）

## 書式の正本はここではない

**書式そのものは [.agents/skills/writing-interim-artifacts/SKILL.md](../../../.agents/skills/writing-interim-artifacts/SKILL.md) にある。先にそれを読む。**

正本を `.agents/` に置いているのは、**同じ書式を Claude Code・codex・Antigravity の3者が使うためである。** 3者が読める場所は `.agents/` だけである。ここに写しを持つと、直したそばから食い違う。

正本に書いてあるのは次の4つである。

| 項目 | 中身 |
|---|---|
| 置き場所とファイル名 | `research/orchestration/<題材>/` の8ファイル |
| 冒頭のメタ情報 | 題材、答える問い、調べた者、調べた日、調べた範囲 |
| 主張の表 | 主張ID、主張、根拠の所在、確からしさ |
| 答えられなかったこと | 「調べていない」と「調べたが見つからない」を分ける |

## 司会だけが行うこと

外部AIは自分ではファイルを置かない。**`30-codex.md` と `31-antigravity.md`、`41` と `42` を置くのは司会である。**

置く前に、次の3つを確かめる。

### 1. 転載が混ざっていないか

**連続する3文以上をそのまま写した箇所が無いかを見る。** `research/orchestration/` はGitで追跡するため、外部AIが書籍の本文を写していると、原本の複製が公開範囲に出る。

見つけたら、その行を要約に置き換え、置き換えたことをファイルの末尾に注記する。**黙って直さない。** 外部AIの主張と司会の書き換えを、あとから切り分けられなくなる。

### 2. 確からしさが正しく付いているか

**`research/extracted/` から引いた主張が「二次資料」になっていないかを見る。** 抽出テキストは書籍の本文であり、一次資料である。実測では codex がここを二次資料と判定したことがある。

誤っていたら直し、直したと注記する。ここが偏ると、議論の決着が公開情報の側へ寄る。

### 3. 批評の原文を書き換えていないか

**`41-codex-critique.md` と `42-antigravity-critique.md` は原文のまま置く。** 書式が崩れていても直さない。司会が書き換えると、決着の根拠が司会の解釈なのか外部AIの主張なのかを切り分けられない。

## 確かめること

- [ ] 外部AIの成果物に3文以上の転載が無い
- [ ] 抽出テキストからの主張が「一次資料」になっている
- [ ] 批評の原文を書き換えていない
- [ ] 書き換えた箇所に注記がある
