| D-1 | 同意 | 探索や比較などの自由な操作はオブジェクト起点とし、順序と完了条件が固定された入力はタスク指向とするなど、操作単位で使い分けるべきである。 | `C-Q1-09`, `B-13`, `W-10` |

| D-5 | 反対 | 前者は「動詞→名詞」の操作構文順序を指し、後者は関心事ごとに入力単位を小分けにする設計を指しているため、両者は同一概念ではなく実際に対立もしていない。 | `C-Q1-08`, `B-03`, `B-47` |
| D-6 | 反対 | 対象のプロパティが少なく一覧で完結する場合や、単一インスタンスで選択が不要な場合には、それぞれ詳細や一覧を省略してよい。 | `C-Q3-02`, `B-20`, `A-16`, `A-17` |
| D-7 | 反対 | 最も浅く広い構成より中位の深さの構成が優れるとする実験結果が存在し、普遍的な段数の数値目安も確認できないため、無条件に「浅く広く」を原則化して数値を定めることには反対である。 | `W-35`, `C-Q3-07`, `C-Q3-10` |
| D-8 | 反対 | クリック数と探索の成功率や満足度の間に有意な相関はなく、指標とすべきはクリック回数ではなく目的への到達性や認知負荷を含めた総インタラクションコストである。 | `W-32`, `W-33`, `C-Q3-08`, `A-21` |
| D-9 | 同意 | UIモデルとドメインモデルは内部実装の隠蔽により完全には一致しないため、そのズレを異常とみなすのではなく、双方向からモデルと画面を洗練させる設計の手がかりと捉える見解に同意する。 | `B-33`, `B-40`, `C-Q4-08`, `A-28` |
| D-10 | 同意 | 無闇なデータクラスの導入は避けるべきだが、複数のドメインオブジェクトを束ねる複合画面や画面固有の表示状態を管理する場合にはビュー専用オブジェクトを置くべきである。 | `B-44`, `W-45`, `C-Q4-03` |
| D-11 | 反対 | ドメインオブジェクトが担うべきは業務ルールに基づく論理的な状態や構造の判定までであり、CSSのclass名のような物理的な表示層の関心事を持たせることには反対である。 | `W-41`, `W-43`, `B-42`, `A-27` |
| D-12 | 同意 | 低頻度かつ非熟練の利用者には手順を誘導するウィザードが適し、高頻度かつ熟練の利用者には対象を並べて自由に操作させる形が適するという判断基準は複数の一次・二次資料で一致している。 | `W-67`, `W-61`, `W-64`, `A-31` |
| D-13 | 反対 | 公開手続きサービスでは有効な手法であるものの、反復して素早い切り替えを要する業務システムの熟練者にとっては非効率となるため、一律の既定とすることには反対である。 | `W-37`, `W-66`, `W-38` |
| D-14 | 反対 | 検索結果画面は対象を束ねたコレクションビューの一種であり、検索は目当てのオブジェクトへ迅速に到達するための補足経路であるため、両者は対立しない。 | `B-24`, `C-Q3-06`, `A-15` |
