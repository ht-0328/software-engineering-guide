## 依頼元の中心の問い

**中心の問いは1つである。フロントエンド・BFF・API のどれに置くか迷ったとき、何を根拠に決めるのか。** 以下の問いは、この1問を答えられる大きさに割ったものである。

## 先に書いた章との関係

**章「01 良いコードとは何か」（接頭辞 `GC-`、観点17件）と章「02 設計」（接頭辞 `DS-`、観点16件）が公開ずみである。** この章の接頭辞は `AR-` とする。

**章02 は、次の5つを「この章で扱わないこと」に入れ、この章へ送っている。** この章はその続きを引き受ける。

## 答える問い

| 問い | 内容 | 主に答える系統 |
|---|---|---|
| `Q1` | フロントエンド・BFF・API の責務を、それぞれ何と定めるのか。境界を引く基準は何か。「画面のため」と「業務のため」をどう切り分けるのか | 書籍 |
| `Q2` | BFF はどういうときに要り、どういうときに要らないのか。BFF を置かない判断はいつ正しいのか。BFF が肥大化する兆候は何か | 書籍 |
| `Q3` | 業務ルール（判定、計算、バリデーション）はどこに置くのか。画面に近い側と遠い側で置き分ける基準はあるか。同じ規則を両側に置いてよいのか | 書籍 |
| `Q4` | 層をまたぐ構造を決めるとき、何を見て決めるのか。品質特性、変更の頻度、チームの分かれ方のうち、何が判断材料になるのか。判断をどう記録するのか | 書籍 |
| `Q5` | 層の間でやり取りする値の形をどう決めるのか。画面向けにまとめた形と、資源の単位にそろえた形の、どちらをいつ選ぶのか | 書籍 |

**問いは4系統すべてに同じものを渡す。** 「主に答える系統」は重み付けであり、担当の分割ではない。

**依頼元が最も迷っているのは `Q1` と `Q2` である。** 調査の重みをこの2つに置く。

## 例示に使う言語

**サンプルコードは Java で書き、悪い例と良い例を対で示す。** ただし Java は例示のための言語であり、原則そのものは言語に依らない。実在の製品名やフレームワークに依存しない素の Java で書く。

コードは10行から25行程度にする。**フロントエンド側の例も Java で書く。** Java で書けないもの（層の関係、呼び出しの流れ、やり取りする値の形）は、Mermaid の図、`text` のブロック図、または表で示す。
