## 中心の問い

**中心の問いは2つである。「言われたことの裏にある解くべき問題を、どうやって取り出すのか」と「起きている事象から原因へ、手当たり次第でなくたどるにはどうするのか」である。** 以下の問いは、この2問を答えられる大きさに割ったものである。

## 答える問い

| 問い | 内容 | 主に答える系統 |
|---|---|---|
| `Q1` | 言われた要望の裏にある本当の問題を、どうやって見つけるのか。掘り下げの手順、質問の型、確かめ方はあるか。要望（解決策の形で語られるもの）と、解くべき問題を、どう区別するのか。掘り下げをどこで止めるのか | 書籍 |
| `Q2` | 具体と抽象をどう行き来するのか。具体に寄りすぎると何が起きるか。抽象に寄りすぎると何が起きるか。往復するための具体的な操作（言い換え、例示、分類、階層を上げ下げする問い）はあるか | 書籍 |
| `Q3` | 不具合の原因をどう切り分けるのか。手当たり次第に試さないための順序はあるか。仮説を立てて確かめる手順、範囲を半分ずつ狭める方法、再現条件を最小にする方法、観測できる情報を増やす方法について、資料は何と言っているか | 公開情報 |
| `Q4` | 「問題が無い」と「問題を見つけられていない」を、どう区別するのか。観測できていないだけの状態をどう検出するのか。証拠の不在を不在の証拠と取り違えないための手立てはあるか | 公開情報 |
| `Q5` | 問題の見つけ方が失敗するときの型は何か。原因を1つに決めうちする、直近の変更だけを疑う、症状に対処して原因を残す、といった型に名前と根拠はあるか。**悪い例と良い例を対で示せる材料**（要望の聞き取りのやり取り、原因の切り分けの進め方、ログの取り方、例外の握りつぶし、再現の最小化）は何か | 公開情報 |

**問いは4系統すべてに同じものを渡す。** 「主に答える系統」は重み付けであり、担当の分割ではない。

**依頼元が最も迷っているのは `Q1` と `Q4` である。** 調査の重みをこの2つに置く。

## 例示に使う言語

**この章は2種類の例を、悪い例と良い例の対で示す。**

| 例の種類 | 書き方 |
|---|---|
| やり取りの例（要望の聞き取り、原因の切り分けの進め方） | ` ```text ` のブロックまたは引用 |
| Java のコード | ` ```java ` のブロック。素の Java で10行から25行 |

**Java のコードは、原因の切り分けに関わる観点にだけ付ける。** ログの取り方、例外の握りつぶし、再現のための最小化などである。**題材に合わない観点に無理にコードを付けない。** その場合は表か手順の一覧で示す。

**どちらも、そのあとに「なぜ悪いのか」「なぜ良いのか」を文章で説明する。** 並べるだけにしない。
