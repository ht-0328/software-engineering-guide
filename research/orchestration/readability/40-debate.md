| 決着のさせ方 | 根拠の強さ、独立性、保留の3つ。多数決では決めない |

| 系統 | 参加 | 成果物 |
|---|---|---|

**書籍の調査は行っていない。** 題材が文書の書式であり、根拠は姉妹リポジトリの標準と公開情報にある。手元の22冊のうち文書の書き方を扱う4冊は、姉妹リポジトリが読み込みずみである（`research/sources.md`）。

## 論点と決着

### D-1 「3行で」を何に改めるか

| 者 | 立場 |
|---|---|
| 司会 | 「結論」。標準自身の各章が同じ位置で使っている（`S-03`） |
| codex | 「結論」。ただし件数を3に固定しない（`C-Q3-02`） |
| Antigravity | 「この章の結論」 |

**決着**: **「結論」とする。件数は固定しない。**

理由は根拠の強さである。`S-03` は標準の実物であり、`docs/03-structure.md` と `docs/05-presentation.md` の両方が冒頭に「結論」を置いている。**「この章の」は、章の中にある見出しとして冗長である。** 3件固定をやめる点は3者が一致した。`C-Q3-02` が示すとおり、3件という数は `SRC-WRITE-001` だけに由来する目安である。

### D-2 根拠をどこに、どう書くか

| 者 | 立場 |
|---|---|
| 司会 | 本文の地の文で書名を名乗らせ、項目の末尾にIDとページを1行で置く（`S-07` から `S-10`） |
| codex | 末尾の根拠行はIDとページのみ。書名は章末の索引で対応させる（`C-Q1-02`） |
| Antigravity | 見出しの直下に書名つきの根拠行を置く（`A-01`、`A-02`） |

**決着**: **司会案を採る。2者の批評とも司会案を支持した。**

- 本文では書名を地の文で名乗る。『リーダブルコード』は…、のように書く。**出典IDを本文に置かない。**
- 項目の末尾に `**根拠**: <出典ID> <ページ>（<節>）` を1行だけ置く。
- 章末の「出典」表が、出典ID・書名・該当箇所・支持する観点IDを対応させる。

この形は `CLAUDE.md` 規則1（主張に出典IDと該当箇所を添える）を満たす。**規則は添える場所を指定していない**（`S-09`）。書名を読者に見せよという過去の指示も、地の文と章末の表の2か所で満たす（`S-10`）。

**Antigravity 案を採らない理由は重複である。** 書名を根拠行と本文の両方に置くと、同じ事実が1つの観点の中に2回出る。実際、Antigravity の書き直し例は本文中に「同書 p.24」「p.25、p.110」を残しており、**指摘3を部分的にしか解消していない。**

### D-3 「観点の一覧」を章のどこに置くか

| 者 | 立場 |
|---|---|
| 司会 | 末尾へ移す（`S-11` から `S-13`） |
| codex | 冒頭付近に「観点を探す」として残す |
| Antigravity | 冒頭に残す（`A-11`） |

**決着**: **末尾へ移す。索引として置く。** 2者の批評とも司会案に変わった。

理由は3つある。標準の `C-07` が箇条書きを7項目以内としているのに対し、この一覧は最大56行ある（`S-11`、`S-12`）。標準の `A-13` が禁じる「冒頭で同じことを2回言う」に当たる（`S-13`）。そして Diátaxis の言うリファレンスであり、**作業しながら引くものは、読み進める入口には向かない**（`W-07`、`W-15`）。

### D-4 8章の形をどこまでそろえるか

| 者 | 立場 |
|---|---|
| codex | 外枠と参照規則だけ共通。本文の順序と表現は章ごとに変える（`C-Q5-01` から `C-Q5-03`） |
| Antigravity | 大枠は統一を維持する。章ごとに変えるのは害である（`A-14` から `A-16`） |

**決着**: **対立していない。** Antigravity 自身が批評で「両者は実質的に合致している」と述べ、`A-16` が「章ごとの柔軟性は、大枠ではなく観点内部の補助形式で満たす」と書いている。

採る形は次のとおりである。**節の並びは8章で共通にする。節の中の書き方は、観点ごとに必要なものだけを置く。**

### D-5 太字の定型ラベルをやめるか

**codex だけが挙げた**（`C-Q4-04`）。根拠は W3C の SC 2.4.10（節の見出し）である。**2者の批評とも同意した。**

**決着**: **節を表すものは太字ラベルにせず、Markdown の見出しにする。**

- 「何を見るか」「なぜそう言えるか」「判断に迷う例」の3ラベルを廃止する。
- 適用の境界など、独立した節が要る観点にだけ `####` の見出しを置く。
- **`**根拠**:` の1行は残す。** これは節ではなく行の頭の札であり、標準自身も `**出典**:` を同じ形で使っている。

### D-6 冒頭に何を置くか

**codex だけが挙げた**（`C-Q3-01`）。**2者の批評とも同意した。**

**決着**: **読者に向けたものを先に、保守のためのものを後ろに置く。**

- 章の先頭は h1 の直後に導入の地の文を置く。
- 「この章で判断できること」を最初の節にする。**想定読者と、読んだあとに何が言えるようになるかを具体で書く。**
- 作成者、機密区分、保守責任者、最終確認日は、章の末尾の「文書情報」へ下げる。

`doc_lint` の `document_metadata` は `templates/`、`docs/index.md`、`docs/adr/`、`README.md` だけを対象にしており、**章はメタ情報の表を冒頭に置く義務を負っていない。** 標準の `C-08`（必須の4要素）は、末尾の「文書情報」で満たす。

### D-7 現在の書式は標準に違反しているか

**司会だけが挙げた**（`S-01` から `S-16`）。**2者の批評とも同意した。**

**決着**: **違反している。7件である。** したがってこの作り直しは、好みの調整ではなく標準への適合である。

| 規則 | 違反の内容 |
|---|---|
| `C-02` 見出しは内容を予測できる具体的な言葉にする | 「3行で」は分量を示し、内容を示していない |
| `C-07` 一度に示す項目は絞る | 「観点の一覧」が最大56行ある |
| `C-09` 走査できるようにする | 同じ小見出しが565個あり、走査の手がかりにならない |
| `A-11` 抽象的な分類だけで具体が無い | 「判断に迷う例」を全項目に義務づけている |
| `A-12` 読者が知らない前提を省いている | 「できること」が観点IDを前提にしている |
| `A-13` 件名と冒頭で同じことを2回言う | メタ情報、「3行で」、「観点の一覧」が3回同じことを言う |
| `A-15` 見出しが「その他」「補足」「詳細」 | 「3行で」が同じ型である |

### D-8 Diátaxis の解決策を採るか

| 者 | 立場 |
|---|---|
| 司会 | 混在が症状の説明である。解決は類型を分けること（`W-13` から `W-15`） |
| codex | **反対。** 症状の説明には同意するが、解決は分離だけではない |
| Antigravity | 同意 |

**決着**: **診断は採る。解決は「文書を分ける」ではなく「章の中で役割の置き場所を分ける」とする。**

codex の反対は妥当である。`W-15` は司会自身が「解決の向きは2つある」と書いており、**分離だけが解ではない。** 文書を2本に割ると、観点IDから説明への行き来が切れる。

採る形は `D-3` の決着と同じである。**読み進める説明を本文に置き、引くためのリファレンスを末尾の索引に置く。** 1つの章の中で置き場所を分ける。

### D-9 観点190件を絞るか

| 者 | 立場 |
|---|---|
| codex | **見落とし。** 重要な観点に絞り、残りを索引へ寄せれば、量の圧迫と類型混在を同時に緩められる |
| Antigravity | **反対。** 内容を維持する前提に反し、参照性を損なう |

**決着**: **絞らない。Antigravity の反対を採る。**

理由は制約である。依頼した人は「今の内容が悪いと言ってるわけではない」と明言しており、`00-plan.md` の制約表にも「内容は変えない。見せ方だけを変える」と書いてある。**観点を索引へ降格させることは、見せ方ではなく内容の変更である。**

**量の問題は `D-3` で扱う。** 一覧を末尾へ移し、節ごとに導入の地の文を置く。**読者が全部を順に読まなくてよいことを、構成で示す。**

### D-10 初出の専門用語に言い換えを添えるか

codex（`C-Q4-02`、W3C SC 3.1.3）と Antigravity（`A-13`）の両方が述べている。**根拠は W3C の1件であり、2者の一致は2票ではない。**

**決着**: **添える。** この手引きに用語集は無く、初めて読む人が語の意味を引く先が無い。**初出の語に短い言い換えをその場で添える。**

## 決着しなかった論点

**無い。** 12件すべてに決着が付いた。

**ただし `D-9` の決着は、制約によるものであって根拠によるものではない。** 観点を絞ることの是非そのものは判定していない。依頼した人が「内容を変えてよい」と言えば、結論は変わりうる。

## 検分で見つけた欠陥

**Antigravity の成果物に2件、書き換えずに記録する。**

| 番号 | 内容 | 扱い |
|---|---|---|
| 1 | 出典IDを独自に採番し、台帳と衝突させた。`SRC-EXT-001` を Google のスタイルガイドとしたが、`research/sources.md` では NIST SP 500-235 である。同じ回答の中で NIST として使っている箇所もあり、一貫していない | 根拠に使わない |
| 2 | 制約の確認表に「検査で error 0 を確認した」と書いた。**Antigravity は Docker を動かせない。** 実行していない | 根拠に使わない |

**2件とも、Antigravity 自身が批評で認めた**（`D-11`、`D-12` に同意）。

**3文以上の転載は無い。** 購入者ウォーターマーク（メールアドレス）の混入も無い。

## 決めた書式

```text
# <番号> <題名>

<導入の地の文。この章が要る場面を具体で書く。1段落>

## この章で判断できること     ← 想定読者と、読後に言えるようになること
## 結論                     ← 件数は固定しない。地の文
## <主題ごとの節>            ← 節の頭に導入の地の文を置く
### <観点ID> <観点を文で書いた見出し>
    結論を先に出す地の文。1段落1アイデア。
    必要な観点にだけ、悪い例と良い例・表・図・#### の小見出しを置く。
    **根拠**: <出典ID> <ページ>（<節>）
## この章で扱わないこと
## 決着していないこと
## 観点の一覧               ← 索引。冒頭から末尾へ移した
## 出典                     ← 出典ID・書名・該当箇所・支持する観点
## 文書情報                 ← 作成者・機密区分・保守責任者・最終確認日
```

**変えないもの**: 観点IDと、観点190件の中身と、根拠そのものである。
