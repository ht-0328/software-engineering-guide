## きっかけ

依頼した人からの指摘である。**内容が悪いという指摘ではない。** 出典も検査も通っているのに読み通せない、という形の問題である。

| 番号 | 指摘 |
|---|---|
| 1 | 冒頭の「この章を読んだあとできること」の内容が薄すぎる |
| 2 | 「3行で」という見出しがださい |
| 3 | `SRC-CODE-001` p.23-24（1.1、1.2）のような表記が多すぎて何が何だか分からない |
| 4 | 何でもかんでも同じ構成なのは読み物としてどうなのか。「何を見るか」「なぜそう言えるか」「判断に迷う例」がずっと続く |
| 5 | 初心者でも読みやすくなる工夫が欲しい |

**「難しい言葉を使うな」という話ではないと明言されている。** 語彙の平易化ではなく、書式と構成の設計の問題である。

## 答える問い

| 問い | 内容 | 主に答える系統 |
|---|---|---|
| `Q1` | 出典の追跡可能性を落とさずに、本文中の出典表記を減らすにはどう置けばよいか | 公開情報 |
| `Q2` | 全観点を同じ3つの小見出しで書く形をやめるとしたら、何に置き換えるか。観点IDによる参照可能性は保つ | 書籍・公開情報 |
| `Q3` | 章の冒頭に何を置けば、読者はその章を読むかどうかを判断できるか | 公開情報 |
| `Q4` | 初心者が読み進められる技術文書は、書式の面で何をしているか | 公開情報 |
| `Q5` | 8章すべてを同じ書式でそろえる方針自体を変えるべきか。章ごとに形を変える利点と害は何か | 3者の判断 |

## 守らなければならない制約

**これを壊す案は採れない。**

| 制約 | 出所 |
|---|---|
| 主張には出典IDと該当箇所を添える。出典が無い記述は「出典なし・私見」と明記する | `CLAUDE.md` 規則1 |
| 出典IDだけでなく書名も読者に分かるようにする | 依頼した人の過去の指摘 |
| 観点IDは残す。他章から参照しており、レビューの指摘からも指せる必要がある | `docs/index.md` |
| `doc_lint.py` が error 0 で通る。常体、曖昧な語の禁止、表のセルは2文まで、h1は1つ、見出しは4段まで、見出しの直後に本文 | `.doclint.yml` とサブモジュールの標準 |
| 内容（観点190件の中身と根拠）は変えない。**見せ方だけを変える** | 依頼した人の指摘「今の内容が悪いと言ってるわけではない」 |
