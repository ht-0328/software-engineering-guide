## 状況

このリポジトリは、システム開発の進め方を書籍とWebの情報から整理して手引きにする。**初回セットアップの時点で、本文はまだ1章も無い。**

| 項目 | 内容 |
|---|---|
| 手元にある一次資料 | 書籍22冊のPDF（`references/`、Git管理外） |
| すでにあるもの | 文書の書き方の標準（サブモジュール `engineering-docs-standard`） |
| 主な書き手 | AI。人はレビューと判断を担う |
| 想定する寿命 | 数年。技術の流行より長く保つ |

決めておかないと後で困ることが3つある。**根拠のたどり方、文書の書き方の規則、そして章の足し方である。** これらを章ごとに決めると、章の間で食い違う。

## 決定

**次の4つを決める。**

| 項目 | 決定 |
|---|---|
| 根拠 | 主張には出典IDと該当箇所を添える。IDの体系は [出典カタログ](../../research/sources.md) が持つ |
| 文書の書き方 | サブモジュール `engineering-docs-standard` の標準に従う。この規則はここには複製しない |
| 言語 | 本文は日本語で書く。ファイル名とディレクトリ名は英語の小文字とハイフンで書く |
| 道具 | 検査と抽出はサブモジュールのスクリプトを呼び出す。このリポジトリには薄い入口だけを置く |

フォルダの役割は次のとおりである。

| 場所 | 役割 |
|---|---|
| `docs/` | 手引きの本文。Markdownが正本 |
| `docs/adr/` | このリポジトリ自身の決定記録 |
| `research/sources.md` | 出典カタログ。出典IDの採番はここが一次情報 |
| `research/notes/` | 書籍から抽出した一次ノート。出典ID1件につき1ファイル |
| `research/external/` | 公開情報の調査結果。URLと確認日を必ず書く |
| `research/extracted/` | PDFから取り出した本文（Git管理外） |
| `templates/` | 章と観点の書式 |
| `tools/` | 検査と抽出の入口 |
| `references/` | 参考書のPDF（Git管理外） |

## 理由

| 判断基準 | 根拠 | 評価 |
|---|---|---|
| 根拠をたどれるか | 出典IDと該当箇所があれば、原本のページに戻れる | 書き手が交代しても検証できる |
| 規則が食い違わないか | 文書の書き方は姉妹リポジトリだけが持つ | 同じ規則を2か所で直す必要が無くなる |
| 道具の重複 | サブモジュールに検査と抽出のスクリプトがある | 写しを持つと、直した側だけが新しくなる |
| 著作権 | PDFは購入者ウォーターマークを含む | Gitに入れず、長文の転載もしない |

## 結果と影響

| 方向 | 内容 | 影響する対象 |
|---|---|---|
| 良くなること | 章をまたいで書式と根拠の示し方がそろう | 読者、書き手 |
| 良くなること | 文書の検査を最初から動かせる | 書き手 |
| 悪くなること | サブモジュールを取得しないと道具が動かない | クローンした人 |
| 悪くなること | 出典の抽出が終わるまで本文を書き始められない | 進みかた |

**サブモジュールを取得していない場合、検査と抽出は動かない。** [README](../../README.md) に取得手順を書いてある。

## 章を足すときの手順

1. `research/extracted/` に本文を取り出す。道具は `tools/extract_pdf.py` である。
2. 読んだ範囲と要点を `research/notes/<出典ID>.md` に書く。**どこまで読んだかを冒頭に書く。**
3. 2冊以上のノートを突き合わせ、共通する原則と食い違いを `research/cross-reference.md` に記録する。
4. `docs/` に章を書く。書式は [docs/index.md](../index.md) の「章の書き方」に従う。
5. 検査を通す。`docs/index.md` の章の一覧の状態を更新する。

**3を飛ばして章を書かない。** 1冊だけを読んで書くと、その本の主張が定説なのか、その著者の立場なのかを区別できない。

## 検討したが採らなかった案

| 案 | 利点 | 採らなかった理由 |
|---|---|---|
| 文書の書き方の規則をこのリポジトリにも書く | サブモジュールが無くても読める | 規則が2か所になり、食い違う |
| 道具をサブモジュールから写す | 依存が減る | 直した側だけが新しくなる |
| 出典IDを分野で分けず通し番号にする | 採番が単純である | IDから分野が読めず、章との対応を見失う |
| 本文を英語で書く | 原著と用語がそろう | 読者は日本語で読み書きしており、読む速さが落ちる |
