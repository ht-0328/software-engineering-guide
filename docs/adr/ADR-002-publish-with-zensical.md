# ADR-002 サイトをZensicalで作り、GitHub Pagesで公開する

| 項目 | 内容 |
|---|---|
| 発信日 | 2026-09-02 |
| 作成者 | Claude（Opus 5） |
| 機密区分 | 公開可 |
| 保守責任者 | このリポジトリの保守担当 |
| 最終確認日 | 2026-09-02 |
| 想定読者（宛先） | このリポジトリの公開手順を保守する人 |
| この文書を読んだあと読者ができること | サイトの作られ方と、公開が止まったときの見る場所が分かる |

## 状況

**手引きは読まれてこそ価値がある。** GitHub上でもMarkdownは読めるが、全文検索と目次が無く、章をまたいで探せない。

| 項目 | 内容 |
|---|---|
| 公開する内容 | `docs/` の本文。書籍の本文は含まない |
| 読者 | 開発者。社外にも公開する |
| 置き場 | GitHub Pages（リポジトリは公開設定） |
| 使える道具 | 姉妹リポジトリが持つ生成スクリプト2種（自作とZensical） |

姉妹リポジトリは、自作の生成器とZensicalの両方を並べている。どちらを残すか比べるためである。**このリポジトリは比較の場ではなく、1つに決める必要がある。**

## 決定

**Zensicalでサイトを作る。** 公開は GitHub Actions から GitHub Pages へ行う。

| 項目 | 決定 |
|---|---|
| 生成器 | Zensical 0.0.57（版は `tools/Dockerfile` で固定する） |
| 公開先 | `https://ht-0328.github.io/software-engineering-guide/` |
| 公開の起点 | `master` への push、および手動実行 |
| 設定 | `zensical.toml`。章を足したら `nav` にも足す |
| 入口 | `tools/build_site.py`。下ごしらえはサブモジュールの実装を呼ぶ |
| 道具の環境 | このリポジトリの `tools/Dockerfile` に1つだけ持つ |

**取り込み前の検査は別の workflow で行う。** プルリクエストでは公開せず、検査とサイト生成が通ることだけを確かめる。

## 理由

| 判断基準 | 根拠 | 評価 |
|---|---|---|
| 書く量 | Zensicalは設定ファイル1つで済む | 生成器を自分で保守しなくてよい |
| 検索 | 生成物に全文検索の索引が付く | 章をまたいで探せる |
| 外部への通信 | 書体を読み込ませず、Mermaidを同梱する | 閲覧時に外部へ通信しない |
| 見出しのアンカー | 検査と同じ規則（`mdslug`）を使う | 本文中のリンクが切れない |
| 乗り換えやすさ | 正本は `docs/` のMarkdownである | 生成器を替えても本文は残る |

道具の環境は1つのイメージにまとめた。**道具は検査・抽出・サイト生成の3つしか無く、分けても得るものが無いためである。** 姉妹リポジトリが2つに分けているのは、生成器を2つ比べているためである。

## 結果と影響

| 方向 | 内容 | 影響する対象 |
|---|---|---|
| 良くなること | 検索と目次のある形で読める | 読者 |
| 良くなること | 取り込み前に、検査とサイト生成の両方が通ることを確かめられる | 書き手 |
| 悪くなること | Zensicalは0.0.57時点でAlphaであり、破壊的変更が起こりうる | 公開手順 |
| 悪くなること | 章を足すとき `zensical.toml` の `nav` も直す必要がある | 書き手 |

**公開する前に、リポジトリの設定を1つ変える。** Settings > Pages の Source を「GitHub Actions」にする。設定しないと配信の段階で失敗する。

**Zensicalが動かなくなった場合は、姉妹リポジトリの自作生成器に戻せる。** 同じ `docs/` を入力にするためである。戻す判断をしたときは、このADRを更新する。

## 検討したが採らなかった案

| 案 | 利点 | 採らなかった理由 |
|---|---|---|
| GitHubのMarkdown表示のままにする | 何も作らなくてよい | 全文検索と目次が無く、章をまたいで探せない |
| 姉妹リポジトリの自作生成器を使う | Alphaの道具に依存しない | 生成器の保守が要る。検索の作り込みも自前になる |
| MkDocs Material を直接使う | 利用例が多い | 姉妹リポジトリと道具が分かれ、設定を2通り覚えることになる |
| 検査用とサイト生成用でイメージを分ける | 依存が混ざらない | 道具が3つしか無く、作る手間だけが増える |
